Reduce Bundle Size

article_service

Hvordan måler man det?

Image-størrelse (lokalt)docker images happyheadlines/article_service:dev
Pull-størrelse (komprimeret)docker save happyheadlines/article_service:dev | gzip | wc -c
→ Pull-størrelsen er bytes / 1.000.000 = MB.
Før og efter er bygget og målt på samme Docker-version.

Før

Standard .NET runtime (Debian)
16# Final stage
17FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS final
18WORKDIR /app
19COPY --from=build /app .
20ENTRYPOINT ["dotnet", "ArticleService.dll"]
353 MB
Image-størrelse (lokalt)
Pull-størrelse (komprimeret, målt)
100,4 MB (0,100 GB)
Estimeret CO₂e pr. pull
≈ 1,42 g CO₂e

Efter

Mindre runtime (chiseled Ubuntu)
16# Final stage
17FROM mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled AS final
18WORKDIR /app
19COPY --from=build /app .
20ENTRYPOINT ["dotnet", "ArticleService.dll"]
193 MB
Image-størrelse (lokalt) · −45 %
Pull-størrelse (komprimeret, målt)
59,7 MB (0,060 GB)
Estimeret CO₂e pr. pull
≈ 0,84 g CO₂e
40,5 %
mindre

Beregning (pr. pull)

0,100 GB × 0,114 kWh/GB × 124 g/kWh
= 1,42 g CO₂e (før)

0,060 GB × 0,114 kWh/GB × 124 g/kWh
= 0,84 g CO₂e (efter)

Alle 6 .NET-services: 0,597 GB → 0,353 GB
= 8,4 → 5,0 g CO₂e pr. fuld deploy

Resultat

  • 45 % mindre image (353 → 193 MB)
    og 40,5 % mindre pull (100,4 → 59,7 MB)
  • ≈ 0,57 g CO₂e sparet pr. pull, ≈ 3,4 g pr. fuld deploy af alle 6 services
  • Samme workload i 15 min: 0 fejl. CPU og RAM er uændret.
  • Ændringen er én linje pr. Dockerfile.

Bemærkninger

  • Sustainable Web Design Model v4: datacenter + netværk = 0,055 + 0,059 = 0,114 kWh/GB
  • Dansk elnet 2025: ca. 124 g CO₂e/kWh (Electricity Maps)
  • MB er målt. CO₂e er et estimat, og modellen overvurderer formentlig gevinsten ved færre bytes.
  • Besparelsen ganges op med antal noder, replikaer og deploys. GHCR gemmer også hver version.
  • Trade-off: ingen shell i containeren (sværere at fejlsøge), kører som non-root, ingen ICU/tidszonedata.
